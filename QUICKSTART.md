# 🚀 FIKRA AI — Quick Start (Local Production)

Get FIKRA AI running on your own server in about 15 minutes — 100% free
infrastructure (one free Groq API key for the LLM).

## 📋 What you need

| Item | Requirement |
|------|-------------|
| Server | Ubuntu 22.04+ LTS (or Debian 12), 4+ GB RAM, 50+ GB SSD |
| Domain | `your-domain.com` pointing to your server's public IP |
| Ports | 80 (HTTP) and 443 (HTTPS) open in firewall |
| Groq API key | Free at [https://console.groq.com](https://console.groq.com) |

## 📦 Stack (all free)

| Layer | Technology | Cost |
|-------|-----------|------|
| LLM | Groq (`llama-3.1-8b-instant` → `openai/gpt-oss-20b` fallback) | Free tier |
| Embeddings | BGE-small (local, ~130 MB) | Free |
| Vector store | Qdrant (local Docker) | Free |
| Database | PostgreSQL 16 (local Docker) | Free |
| Cache / Broker | Redis 7 (local Docker) | Free |
| Backend | FastAPI + Celery | Free |
| Frontend | Next.js | Free |
| SSL | Let's Encrypt via Nginx + Certbot | Free |

## 🏃‍♂️ One-command deploy

Copy this repo to your server, then run:

```bash
# 1. Copy the repo to your server
git clone <your-repo-url> /opt/fikra-ai
cd /opt/fikra-ai

# 2. Make the deploy script executable
chmod +x scripts/deploy-free-server.sh

# 3. Run it (takes 10–30 minutes)
sudo ./scripts/deploy-free-server.sh your-domain.com your-groq-api-key
```

Replace `your-domain.com` and `your-groq-api-key` with your values.

## 🔄 How Groq fallback works

The app uses **two models** automatically:

1. **Primary:** `llama-3.1-8b-instant` — fast, ~14,400 tokens/minute free tier
2. **Fallback:** `openai/gpt-oss-20b` — used automatically if the primary hits its token/rate limit

If the primary model is exhausted, the backend:
1. Detects the rate-limit error from Groq
2. Waits with exponential backoff
3. Tries the fallback model
4. Returns the answer to you — you never see an error

## 🔐 Security (built in)

| Feature | How it works |
|---------|--------------|
| **Password encryption** | Argon2id hashing (64 MB memory, 3 iterations, 4 threads) — passwords are never stored in plaintext |
| **Data encryption at rest** | Sensitive fields (email, full name, document titles, chat content) are encrypted with Fernet (AES-128-CBC + HMAC) before being written to PostgreSQL |
| **Encryption key** | `DATA_ENCRYPTION_KEY` in `backend/.env` (auto-generated by the deploy script / `setup.ps1`) |
| **Token auth** | JWT access tokens in HttpOnly cookies + rotating refresh tokens |
| **HTTPS** | Let's Encrypt certificate via Nginx + Certbot |

> **Note:** `users.email_normalized` stays plaintext on purpose — login looks users
> up by it. Everything else sensitive is encrypted. Document chunk content is
> kept plaintext because PostgreSQL full-text search indexes it directly.

## 🆘 Troubleshooting

| Problem | Fix |
|-------|-----|
| `/health/live` fails | Wait 60–90 s for backend to start, then retry |
| `/health/ready` 503 | Embedding model is downloading (~130 MB). Wait and retry. |
| Login button disabled | Run `docker compose exec backend python scripts/create_initial_org.py` |
| Chat says "Something went wrong" | Groq token limit hit — fallback kicks in automatically. Wait 10–30 s. |
| SSL failed | Ensure DNS A record points to your server IP, then re-run certbot |
| Out of memory | Reduce `WORKER_CONCURRENCY` to 1 in `backend/.env` |
